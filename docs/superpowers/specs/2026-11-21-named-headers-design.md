# 名前の見出し（北1・Aa・南-1 など）の地点を読む・並べる（lab-kanri 3.41）設計

2026-11-21。依頼＝`~/app_dev/shast-picker-pro/docs/依頼/2026-11-21_lab-kanri_名前のついた行・列（名前の見出し）.md`（picker セッションから）。

## 目的
- picker v3.96 で区画の見出しに名前を付けられるようになる（横 `A,Aa,B`・縦 `北1,1,2,3,南-1`。地点名 `A北1-1`・`B南-1-5`・`Aa2 (2,4,5,6,8)`）。
  ラボの現場（2026年12月初め）で「1N」「2N」などの名前の行を使う。
- 今の lab-kanri は地点名を「英字＋数字」の形（正規表現）で読むので、名前の地点が**表から消える**か**別の区画と読み違える**（`A1N` → `A1`）。
  読み違えは揃いの判定を狂わせるのでいちばん困る。
- 締め切り：12月初めより前に配信。picker の本番（v3.96）は lab-kanri と shast の配信を待つ。

## やること（picker の依頼の 1〜6）
1. 名前の対応表（`pointNames`）のある現場は、地点名を形で読まず、表の地点名（親の名前）を**長い名前から**当てて区画を引く。大文字小文字はそのまま比べる。
2. 中の番号（901・ZZA など）は人の目に出さない（採取マップの見出し・表・一覧・ラベル・読み上げ・履歴）。
3. 並びは `axisOrder`（英字の側の順 → 数字の側の順 → 枝番）。
4. 表の無い現場は今のまま（並び・表・揃い）。
5. 表を読めなかったときは、名前の地点を読み違えるより読めない方がまし。読み違えは起こさない。
6. 読み上げで名前の地点が聞き取れるか確かめる。

## 対応表の読み方（ア：`_picker_data` を読む・2026-11-21 ユーザー決定・picker に通知済み）
- `_picker_data` タブ：A1＝`__PICKER_V1__`、A2＝meta の JSON（`{"chunks":N,"length":…,"savedAt":"…"}`）、A3 から下＝JSON を分けた文字列。
- 大きい（図面入りの現場で 6.9MB／173 個）ので、**毎回は A2 だけ読み、`savedAt` が覚えているものと違うときだけ A3〜を読んで JSON.parse** する。
  覚えるのは `site.grid` の `pointNames`・`axisOrder`・`rowNames`・`colNames`（・`nameFirst`・`nameSep` は使わない）だけ。
  控えは CacheService（キー `lk_grid_<シートID>`・6時間・100KB 以内）。100KB を超えたら控えずに毎回読む（ログに残す）。
- 結果は3通り：
  - `null`：`_picker_data` が無い・`pointNames` が無い ＝ 表の無い現場（今のまま）
  - `{ pointNames, axisOrder, rowNames, colNames }`：表のある現場
  - `{ error: '…' }`：読めない・壊れている（JSON が壊れている・chunks が足りない など）
- サーバーは今ある `getSaishuAll`・`getKentaiData`・`getDailyReportData` の答えに `pickerGrid` を足して返す（アプリの表・マップ・揃いの判定・本日の地点の順はこの3つのデータで作るため）。
  古いアプリは知らない項目を無視する。スキャン（handleScan）は対応表を使わない（コードで引く）ので遅くならない。

## アプリの作り（Claude の判断）
### 案
- **案1（採用）：地点名の読み方を1つの部品にまとめる**（新しいファイル `assets/pointname.js`、`window.PointName`／node の試験）。
  表のある現場用と表の無い現場用の2つの「読み手」を同じ形で持ち、今の8か所はこの読み手を呼ぶだけにする。
- 案2：8か所の正規表現をそれぞれ直す。→ 同じ読み方を8か所に書くことになり、1か所の直し忘れが読み違えになる。採らない。

### 読み手（resolver）の形
`PointName.resolver(pickerGrid)` が返すもの：
- `parse(地点名)` → `{ area, item, suffix }` か `null`（今の `parsePointFull` と同じ形）。
  - 表あり：親の名前を長い順に当て、残りが `-` ＋ 数字1つ（1〜9）＋後ろの印（英字1つと①〜⑨の組み合わせ、今と同じ）のときだけ。`area` は**親の名前**（`B南-1`）。
  - 表なし：今の正規表現そのまま（`^([A-Za-z]+\d+)-(\d+)([A-Za-z]?[①-⑨]?)$`）。
- `areaOf(文字列)` → 親の名前／区画コードか `''`（分析検体の A 列 `Aa2 (2,4,5,6,8)`・`A北1-1`・`K7-2h 3.00-3.50m` から区画を取る。今の `^([A-Za-z]+\d+)` の3か所）。
  - 表あり：親の名前を長い順に当て、そのすぐ後ろが「終わり・空白・`(`・`（`・`-`」のときだけ。
  - 表なし：`^([A-Za-z]+\d+)` の**すぐ後ろが英数字でない**ときだけ（`A1N (…)` を `A1` と読まない。今ある現場の地点名はこの形に収まるので、今ある現場の動きは変わらない）。
- `compareArea(a, b)` → 並び。表あり：`axisOrder` の位置（英字の側 → 数字の側）、表に無いものは後ろ・文字の順。表なし：今と同じ（英字の文字の順 → 数字の数の順）。
- `mapAxes(areaKeys)` → 採取マップの見出しとマス：`{ cols: [{key, label}], rows: [{key, label}], cell(colKey, rowKey) → 区画のキー }`。
  表あり：`axisOrder` の順・見出しの文字は `colNames`／`rowNames` の名前（無ければ中の番号＝ふつうの見出しそのもの `A`・`1`）・マスは `pointNames[英字の側＋数字の側]`。表なし：今と同じ（区画コードを英字と数字に分けて並べる）。
- 表が読めない（`{error}`）とき：表なしの読み手を使う（上の「すぐ後ろが英数字でない」締めで読み違えは起きない。名前の地点は表に出ない）＋ 画面の上に「地点名の対応表を読めませんでした（名前の付いた地点は表に出ていません）」と出す。

### 直す所（index.html）
- `parsePointFull`（採取・受入の 1〜9 マスの表・採取マップ）→ `resolver.parse`
- `kentaiRowKinds`・揃いの判定（`acm`）・区画コード（`areaCodeMatch`）の3か所 → `resolver.areaOf`
- `parseScheduledNums` の単体地点（`-(\d)` の末尾）→ 表ありは `resolver.parse` の枝番を使う（`南-1` のハイフンを枝番と読まない）
- `renderSaishuMap` の見出しとマス → `resolver.mapAxes`
- 区画の並び（`areaCodes.sort`）・一覧の並び（`pointSortKey_`）→ `resolver.compareArea`
- genchi.js の残りの一覧と本日の地点の順 → 地点の比べ方を `resolver.compareArea` に差し替えられるようにする（表なしは今のまま）
- 読み上げ：表ありの地点は「親の名前の読み」＋「の」＋枝番（今の読み方と同じ規則。漢字はそのまま読み上げに渡す）。実機で聞いて確かめる。

### 現場ごとの表の持ち方
- `getSaishuAll`・`getKentaiData`・`getDailyReportData` の答えの `pickerGrid` を、そのシートの ID と一緒に覚え、読み手を作り直す。現場を切り替えたら捨てる。
- 表の無い現場では今の読み手と同じ結果になることを試験で確かめる（今ある現場は1文字も変えない）。

## 試験
- サーバー（node・harness）：`_picker_data` の分割を読む／`savedAt` が同じなら A2 だけ／変わったら読み直す／壊れた JSON は `{error}`／タブ無しは `null`／`pointNames` 無しは `null`。
- アプリ（node）：`pointname.js` の全関数を、依頼の見本（`A北1-1`・`Aa1-1`・`B南-1-5`・`A北1-5h`・`A北1-2①`・`Aa2 (2,4,5,6,8)`・縦が先 `北1A-1`・ハイフン `A-北1-1`・`南-1-B-5`・名前の列 `北1-1`）と、今ある現場の地点名で確かめる。
  特に：`A1` と `A1N`・`Aa1` と `Aa11` を取り違えない、`B南-1-5` を `B南` の 1 と読まない、表なしで `A1N (…)` を `A1` と読まない。
- 実機（Note20・試験用サーバー）：見本のシート（デモ会社）の**写しを自社テストの現場シートのフォルダに作って**開く（開発用のキーはデモ会社のシートを開けないため）。
  1〜9 マスの表・採取マップの見出しと並び・揃い・本日の地点の順・ラベル・読み上げ・履歴に 901・ZZA が出ないこと、今ある現場（旧畜産の写し・深度VOC）が今と同じことを見る。

## やらないこと
- picker・shast の変更。
- `nameFirst`・`nameSep` の解釈（`pointNames` に組み立て済みの地点名が入っているので要らない）。
- ブロック方式（地点自由入力）の現場の扱いの変更（`pointNames` が無いので今のまま）。
