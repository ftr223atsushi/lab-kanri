# 現地確認の「残り」表示と、本日の並べ替え（lab-kanri 3.40）設計

2026-11-18 ユーザーと合意した内容。

## 目的（ユーザーの言葉から）
- 複数の班がその日に掘った検体が、全部ラボの手元に届いたかを、夕方の現地確認で確かめたい。
  草むらに取り残した・途中で落とした袋に気づきたい。
- 今は「本日」で読んだ検体は分かるが、掘った数が分からないので、現地確認が合っているか判断できない。
- 深度は「本日」で深さの数字順に並ばないので、抜けに気づけない。

## 作るもの
### 1. 現地確認モードの「残り」帯（案1・ユーザー選択）
- 置き場所：メイン画面の「スキャン待機中...」の下。工程モードで「現地確認」を選んでいるときだけ出す。
- 表示：`今日掘った N ／ 現地確認 M ／ ⚠ 残り K ▼`（K=0 なら「✓ そろいました」）。
- ▼で残りの一覧：種別（表層→ガス→配管→深度）→地点の順。表層は上→下、深度・配管は深さの数字順。
  右に採取担当（shast で写真を撮った人＝どの班に聞けばよいか）。
- 前日までに掘って現地確認していない袋があれば「前日までの残り n」を別に出し、一覧では日付を添える
  （昨日の取り残しを見落とさない）。
- 読むたびに残りが減る（現地確認のスキャンが成功したら、その場で一覧から消す。サーバーへ聞き直さない）。
  帯に［↻］を付け、押したら読み直す。現地確認を選んだとき・現場を切り替えたときにも読み直す。

### 2. 「本日」の並べ替えの切り替え
- 日報の上に［時刻の順｜地点の順］の切り替え。既定は今までどおり時刻の順。選んだ方を端末に覚える。
- 地点の順＝1 と同じ規則（種別→地点→上下・深さの数字順）。印刷する日報もこの並び。

## 「掘った」と「現地確認」の決め方
データはシートの実データタブ（表層土壌・土壌ガス・配管・ピット・盛土下・深度調査）。
- 掘った ＝「採取日時」が入っている行（shast が書く）。
  - 表層・ガス・配管・地下水（WG/WP）＝その袋・瓶を採った日時。
  - 深度の土の行＝その穴の「掘削完了」の日時（同じ地点の土の行すべてに同じ値）。
    → 掘り終えた穴の、予定の深さの袋は全部あるはずとみなす。
- 現地確認済み ＝「現地確認日時」が入っている行。
- 数えない行：状態が「削除」の行。
- 今日掘った ＝ 採取日時の日付が今日（端末の日付）。現地確認の日付は問わない（翌朝の現地確認も数える）。
- 残り ＝ 掘ったのに現地確認日時が空の行。

## 前提（2026-11-19 ユーザー回答）
- どの班も shast で採取の写真を撮っている。
- 電波が悪く shast の送信が遅れた分は、届くまで「掘った」に入らない（取り残しとしては出ない）＝しかたない。
- 深度で予定より浅く止めた穴は、何もしていない（picker で行を削除していない）。
  → 対策：shast が「掘削完了」タブ（1地点1行）に書く「検測」（実際に掘った深さ）と比べ、
    深度（行の「深度」の最初の数字）が検測より深い袋は「掘った」に数えない。
    一覧の下に薄く「掘った深さ 5.0m より深い予定 3袋（数えていません）」と出す（黙って消さない）。
    検測が無い・数字が読めない地点は、予定の袋を全部数える。

## 作り方（Claude の判断）
- サーバー：今ある `getSaishuAll`（4種の実データの全行）を使う。新しい呼び出しは作らない
  （行には地点・上下・深度・採取日時・採取担当・コード・現地確認日時・状態がもうそろっている）。
  足すのは答えの `depthDone`＝「掘削完了」タブの {地点: 検測}（タブが無ければ {}。状態「削除」の行は除く）だけ。
  古いアプリは知らない項目を無視するので互換。
- アプリ：残りの計算・並べ替えは license.js と同じ「純粋な関数」の小さなファイル（assets/genchi.js）に置き、
  node の試験で確かめる。画面への組み込みは index.html。
- 版：3.40（アプリとサーバーの両方）。

## やらないこと
- 班ごとの集計・班の登録（採取担当の名前を出すだけ）。
- shast 側の変更。
- 「本日」以外の画面（🌱 現地）の変更。
